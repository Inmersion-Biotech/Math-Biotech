# Source, science and content policy

## Ownership and reuse

**Source availability does not imply permission to redistribute every included file.** The future software license can apply only to code that the rights holders are authorized to license. Third-party dependencies retain their original licenses. Trademarks, logos, photographs, external datasets, university course materials, exam documents and media require separate provenance and permission.

Do not copy protected course slides, assessments, publisher illustrations or personal notes into a public release without an explicit rights review. Metadata embedded in PDF, Word, images and other formats may identify authors, devices or organizations even if the visible pages seem anonymous.

## Scientific rigor

Educational diagrams, chemistry structure calculations, botanical renderings and models should distinguish:
- observed or experimentally established information;
- assumptions, simulations and computational output;
- conjectural or illustrative examples.

State uncertainty where it matters and do not imply that an illustration is experimental evidence.

## Privacy and operational security

Remove identities, fixed privileged emails, sample personal accounts, local file paths, deployment project identifiers if not intended for disclosure, debugging exports and access credentials before publishing. Historical commits and tags must be evaluated as well.

For production, keep third-party API secrets behind a reviewed backend. Firebase web configuration is not a secret authorization boundary; enforce access through robust server rules and account permissions.
